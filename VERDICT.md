# VERDICT

Written before building. Grounded in AUDIT.md (full code read + a live
session driving the app with realistic data). Every call below cites the
evidence that earned it; nothing is kept because it exists, and nothing
is rebuilt for the sake of shape.

---

## 1. Per-subsystem calls

**Architecture / state — REBUILD.**
The confirmed bug crop (double-XP at 93/70 credited, task-vs-chunk
completion divergence, `taskIds` reads dead since schema v4 still
driving two features, "day cleared" false-fires) shares one root:
derived quantities stored as mutated counters, maintained by four
parallel completion paths with hand-written inverses. That's an
architecture disease, not a bug list. New core: one store, one
completion mutation, XP/streak/activity as pure derivations from the
completion history. This is the change that makes the whole drift class
*impossible* rather than *currently patched*.

**Persistence — REWORK.**
localStorage-as-primary survives first principles for a single-user
local-first tool: keep it. Kill the async `window.storage` shim (vestige
of the original host), replace ~60 scattered read-modify-write calls
with one debounced per-slice persist, add a 7-slot rotating auto-backup.
Keep and extend the best code in the repo: the additive migration
discipline and the export/import (new app reads quest_* v≤8, vsq_*,
shiplist, and old backup files).

**Six-view IA — REBUILD into three surfaces.**
Live evidence: capture lands invisible (Today shows "0 on today's plan"
seconds after capturing); most actions have two homes with different
semantics; Habits connects to nothing; Trophies is a room you visit
twice a year. New model — the day is the spine:
- **Today**: capture (instant), today's lineup, missed-work triage,
  day-close, momentum. The home screen is the workbench.
- **Plan**: the same tasks arranged in time — agenda-first upcoming
  days, capacity, AI schedule/replan with visible status.
- **Dock**: projects (the ship ritual) + the full library with filters
  (Queue's function, absorbed).
Stats/trophies become a panel, not a view. The screen log stays as the
small Today card it already was (all data preserved, history in the
stats panel) — demoted from nav, not deleted.

**AI layer — REWORK: keep the brains, replace the trust model.**
The surgical replan operations design, chunk-splitting scheduler,
capture parser, project-extend, and vision import all earn their place —
the prompts and applier logic port nearly as-is. What gets rebuilt is
transport and honesty: capture saves locally in 0ms and AI enriches
async (never gates); AI status (ready/off) is visible; failures say what
failed ("AI unreachable — saved, scored manually"), never "try
rephrasing" when the network is down; `/api/anthropic` served by the
same contract in prod (Netlify function, env key) and dev (Vite
middleware, env key, zero new deps). Scoring: deterministic by default,
AI as suggester — an XP economy can't run on unverifiable guesses that
silently flat-line to 20 when a fetch fails.

**Gamification — REWORK: keep the pull, retire the fake precision.**
Keep (evidence: these are the moments that landed even in an audit
session): streak, ship confetti, day-close ritual, week bars, level
identity (he earned Lv.7). Change: all of it becomes derived and
recomputable; the owner's lifetime XP is preserved at migration via a
one-time baseline so his number never visibly drops; trophies fold into
the stats panel with derived progress. The XP double-pay class dies by
construction.

**Ergonomics / input layer — REBUILD.**
"Keyboard-first" currently means switching views. New command layer:
j/k cursor on every list, Enter/x complete, e edit, f focus, s schedule,
d due, Delete with undo-toast (no `window.confirm` anywhere), Ctrl+K
palette, N capture, 1–3 surfaces, ? help — all through the central
store. Capture is instant-local. Mobile gets a usable Today (capture
reachable, one-column lineup) — not a full mobile app, but the 8am
phone check-off works.

**Identity — REPLACE.** See §3.

## 2. The overall call: PARTIAL REBUILD

New foundation and shell, written fresh in `quest-next`; the subsystems
that survived on evidence are *ported through* it, not reinvented:
the weekplan chunk data model, `applyReplanOps` and the planner prompt
family, migration approach, export/import format, focus tunnel,
missed-work triage pattern, preview mode, capture modes, ship flow.

Why not "evolve": the four worst live defects are generated by the
state architecture itself; fixing them in place means rewriting the
middle of a 7.6k-line file while keeping its shape — more risk, less
payoff. Why not "full rebuild from zero": a third of this codebase
(replan applier, migrations, chunk model, the rituals) demonstrably
earned its place and porting it is cheaper and safer than re-deriving
it.

What the rebuild unlocks that the current foundation cannot:
1. A ledger that cannot drift (XP/streak derived, recomputable — also
   makes import/merge trivially correct).
2. Honest offline/degraded AI with instant capture (requires inverting
   the capture flow everywhere).
3. Real keyboard-first (a command layer needs one store, not 40-prop
   drilling).
4. Schema access through one module — the dead-field bug class dies.
5. A phone-usable Today.

## 3. Product identity

**Name: Werf** (Dutch: *shipyard* — the yard where ships are built and
launched). Four letters, the owner's language, and it says what the
product is: not a quest to grind, a yard to launch from. The heritage is
already there — the owner's previous app was literally "shiplist", the
Pipeline's verb is "Ship it", and the README's own words are "personal
OS for shipping."

**Positioning (one line):** *Werf is a single-user shipyard: capture in
zero clicks, plan honestly, launch relentlessly.*

**Design directions considered (three, genuinely distinct):**

- **A. Blueprint** — paper-light technical-drawing aesthetic: blueprint
  blues on near-white, hairline rules, stamped chips, drafting mono.
  Distinct and designer-credible, but the owner demonstrably works past
  midnight (he built a day-rollover feature *because* of it; the audit
  session itself ran at 00:30) — a light-only identity fights his actual
  hours.
- **B. Harbor at night** — dark, but with a point of view: deep
  blue-black water instead of neutral black, one warm harbor-light amber
  as the accent, and *navigation-light semantics doing real work* —
  port red = urgent/overdue, starboard green = done/ready-to-launch,
  channel blue = scheduled/info. Display type with character for the
  greeting/brand, tabular mono for every numeral. Nautical as system,
  not as clip-art.
- **C. Instrument panel** — full terminal cockpit: mono-everything,
  phosphor green/amber, dense ASCII-adjacent charts. Maximum
  keyboard-first energy, but it reads "hacker toy," ages fast, and
  flattens the shipping metaphor the product actually owns.

**Pick: B — Harbor at night.** It fits the owner's real hours (dark,
low-glare), gives the ship metaphor functional teeth (the status system
*is* the harbor lights), keeps enough continuity that migration morning
feels like home-but-better, and is differentiated from the violet
default he has now. A: rejected on the night-owl evidence. C: rejected
as gimmick-over-craft for a professional designer's daily tool.

Tokens (headline): bg `#0B0E14` (blue-black), surfaces `#111624/#161C2B`,
amber accent `#F5A524` (harbor light — actions, focus, streak), port red
`#F0716B`, starboard green `#3FD68F`, channel blue `#5B9DFF`, text
`#E9ECF2/#98A2B8/#5C677D`. Type: Inter (body), Bricolage Grotesque
(display), JetBrains Mono (numerals/data). Radius 6/10px, hairline
borders.

## 4. Hard requirements honored (restated as commitments)

- Migration: `werf_schema v1` migrator ingests quest_* (v≤8), vsq_*,
  shiplist-projects-v2, and quest/werf backup JSON — versioned, runs
  once, lifetime-XP baseline preserved.
- Local-first: `npm install` + `npm run dev` (Vite serves the app *and*
  the AI proxy middleware; `ANTHROPIC_API_KEY` in `.env` enables AI
  locally; without it the app is fully usable and *says* AI is off).
- Server-side key only: Netlify function unchanged in contract; no key
  in client code, ever.
- Keyboard-first: strengthened (command layer above).
- One user: no auth, no flags, no design-system package. Runtime deps
  stay exactly `react` + `react-dom`; dev deps stay `vite` +
  `@vitejs/plugin-react`. Zero new dependencies.
